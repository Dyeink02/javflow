### 分层架构


### 执行链速览（详见第 2-5 节）

- **爬虫（冻结区）**：10 阶段状态机 boot→queue_setup→resume_pending→index_discovery→queue_drain→page_gap_recovery(≤2轮)→queue_gap_recovery→detail_recovery(≤4轮)→second_validation→final_drain；断点续爬 Snapshot 恢复；镜像 fallback 主站→antiblock 列表；磁力大合集内置过滤。
- **整理**：scan 三分类 → 移入待整理（rename-history.jsonl）→ 未命中 → 广告风险审查（adlearning）→ 报告 → 批量删除（32个/批+350ms）→ 空目录收口。
- **刮削（冻结区）**：metatube engine 内嵌，provider 优先级+健康冷却，NFO/poster/backdrop/.actors 头像缓存。
- **订阅**：导入 → 基线 → refresh 对比 → subcrawlv2 增量抓取 → finalize 回写。

## 四、方案一：加强注释

### 4.1 红线（先讲清楚）

以下区域**本轮不写注释、不做任何修改**（核心爬虫/刮削 + Cloudflare/年龄验证，属上游项目带入且为既有冻结区）：

```
internal/crawlfetch / crawlrequest / crawlparse / crawlrunner / crawloutput
internal/crawlidentity / crawlindex / crawlexecution / crawlqueue / crawlconfig
internal/crawltask / crawltaskstate / crawlquality / crawlstage / crawlresult
internal/crawlreview / crawluistate / crawlruncontext / crawlindex / antiblock
internal/librarymetadata（刮削核心）
src/core/requestHandler* / cloudflare* / puppeteerPool / parser / magnetContentValidation
```

> 说明：向冻结区文件添加注释也属于"修改"，默认不做；若你明确授权某个文件可加注释，再逐文件执行。

### 4.2 注释规范（建议统一）

1. **文件头**：每个 .go/.js 文件顶部一个职责块（中文，3-6 行）——本文件做什么、被谁调用、产出什么。
2. **导出符号**：Go 导出类型/函数用 godoc 中文注释（`// Xxx 作用`）；前端模块用 `@module` 风格头注释。
3. **流程注释**：管线阶段（如整理 9 步、订阅闭环）在阶段入口处标注"第 N 步/共 M 步 + 本步职责"。
4. **Why 注释**：只给非显然逻辑写"为什么"（如日志三防线、批量删除 32 个/批的原因、完成弹窗轮次锁），不写"这行代码干什么"的废话注释。
5. **语言**：统一中文，与现有 organizer/bridge 风格一致。
